# 2026.281.0920 — fix(openclaw): bump the gateway pin to 2026.9.8 and assert its engine floor

## Summary

The `openclaw` gateway candy was pinned to npm `openclaw@2026.9.1` and described as "the current latest stable". The stable line has since moved to **2026.9.8** (published 2026-10-03). This PR moves the pin, moves every string that asserted the old one, and makes the requirement the bump *introduces* observable.

- `package.json`: `openclaw` `2026.9.1` -> `2026.9.8`.
- `charly.yml`: the `openclaw --version` assertion regex -> `2026\.9\.8`; the candy `description:` and its `skill:` body stop claiming `2026.9.1` / `2026.8.x`.
- `charly.yml`: the version check loses an unverifiable claim. It read "the exact **security-patched** package version"; it now reads "the exact **pinned** package version", because this bump is not a security release: no `CVE-` identifier appears in any of the 2026.9.2..2026.9.8 release notes (the range is security *hardening* - one Security and Privacy section per release - and one note explicitly says a dependency exception "is not a dependency upgrade or vulnerability fix").
- `charly.yml`: **a new check** - the in-image Node must satisfy openclaw's engine range `>=24.16.0 <25 || >=26.1.0`. The floor **moved at 2026.9.3** and it excludes node 22 and node 25.x. The candy declared only `layer-nodejs`, so that requirement was implied and never asserted; on Debian/Ubuntu that layer installs NodeSource node 22, which the new floor rejects.
- `README.md` and `AGENTS.md`: the four stale version strings, two of which the claim-keyed sweep found rather than the original estimate.

Deliberately not in this PR, in the same cutover (opencharly/opencharly#431): the canonical `check-openclaw-pod` bed lives in `distro-cachyos` and composes the **published** tag `pod-openclaw@v2026.274.0622`, so it cannot see an unmerged branch; it runs with the pin advance in the consumer PR. This PR's gate is an equivalent disposable pod bed that builds this worktree's candy content.
